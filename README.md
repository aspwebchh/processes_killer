# 进程结束工具

Windows 桌面工具，使用 WPF / .NET Framework 4.7.2。包含“进程管理”和“端口查询”两个页签，默认打开进程管理。

## 运行

运行 `bin/Release/ProcessesKiller.exe`，或解压 `artifacts/ProcessesKiller.zip` 后运行其中的程序。需要 Windows 和 .NET Framework 4.7.2 或更高版本。分发时保留同目录的 `ProcessesKiller.exe.config`。

## 进程管理

- 保留进程名筛选、多选结束、结束当前列表、右键结束、列排序和进程类型配色。
- 当前页每 3 秒刷新，后台页暂停，切回立即刷新。
- 在 `ProcessesKiller.exe.config` 的 `TargetProcessNames` 中配置要显示的进程，支持逗号或分号分隔，有无 `.exe` 后缀均可。默认是 `java,javaw,explorer`；刷新时重新读取配置。
- 普通进程沿用直接结束操作；结束 explorer.exe 前弹出确认，取消后不执行。工具不会结束自身。

## 端口查询

1. 选择“全部 / TCP / UDP”，点击“查询”或按 Enter。端口留空（包括纯空格）查询全部；输入 `1–65535` 的整数端口可缩小范围，支持首尾空格。首次进入端口页不会自动查询。
2. 列表只显示进程名、PID、端口、协议和本地地址，支持 IPv4/IPv6。同一进程在同一端口、同一协议下的多个本地地址合并为一行显示，不同端口或不同协议分别显示；默认按进程名、PID、端口排序。查询不受进程管理配置限制。
3. 双击行或右键“查看详情”，查看并复制启动时间、可执行路径和命令行；按 Ctrl/Shift 可多选。不可结束的原因显示在行提示中。
4. 点击“结束选中”，核对进程名、PID 和选中的端口后确认。结束的是整个进程，它的其他端口也会受影响；同一 PID 的多个端点只结束一次。目标较多时确认列表可滚动，默认操作为取消。
5. 完成后重新读取端口表，显示最新占用者。点击状态栏中的结束结果可查看成功、跳过、未退出或失败的原因。

刷新保留仍然存在的选中项和列排序，切换页签保留各页的最近操作结果。修改查询条件后，旧结果标记为待查询并禁用结束操作；重新查询后恢复。

TCP 只展示监听端点，UDP 展示已绑定端点。无匹配结果表示当前未发现所选协议的监听/绑定；查询失败或部分协议读取失败时会明确显示“无法完整确认”，并禁用结束操作。进程路径或命令行读取失败不会隐藏已经查到的端口和 PID。

结束前会重新验证进程名称、启动时间，以及至少一个选中端点仍归属该进程。目标已退出、身份变化，或者选中的端点全部消失时跳过；即使该进程还监听其他未选中的端口，也不会据此结束它。PID 0/4、当前工具和无法验证身份的目标不可结束。权限不足会给出原因，可自行以管理员身份运行后重试；工具不会自动提权或自动反复结束进程。等待退出最多 3 秒，等待期间界面仍可响应。

## 构建与验证

推荐使用根目录下的编译脚本直接编译到 `bin\Release\`：

```powershell
.\build.ps1               # 默认直接编译 Release 到 bin\Release
.\build.ps1 -Rebuild      # 重新完整编译
.\build.ps1 -RunTests     # 编译后自动运行测试
```

也可手动调用 Visual Studio / Build Tools 的 MSBuild：

```powershell
msbuild ProcessesKiller.csproj /p:Configuration=Debug
msbuild ProcessesKiller.csproj /p:Configuration=Release
.\tests\Run-Tests.ps1
```

验证脚本不依赖第三方测试框架，测试程序集和布局 PNG 输出到系统临时目录。服务测试覆盖四种原生端口表、输入边界、全部/指定端口查询、同端口多 PID、选中端点消失、身份变化、权限失败、进程结束和端口被新进程接管。WPF 组件测试在进程内验证空白输入、协议筛选、确认取消、选择/排序保持、并发刷新、部分失败、原有 explorer 确认、自身保护、精简布局、下拉框文字对齐和关闭后的异步处理；只结束脚本创建并选中的临时监听进程。

主要实现：`PortQueryService.cs` 读取 Windows 端口表，`ProcessTerminationService.cs` 验证并结束进程，`MainWindow.Ports.cs` 管理端口页的交互和刷新。
